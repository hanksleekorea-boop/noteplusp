Evernote 자료를 안전하게 옮기는 순서

이전 작업의 목표는 단순히 “가져오기 성공” 메시지를 보는 것이 아닙니다. 원본 수, 제목, 본문, 날짜와 첨부가 실제로 보존됐는지 확인하고, 문제가 생기면 원래 상태로 돌아갈 수 있어야 합니다.

먼저 할 일: 원본 Evernote 데이터는 가져오기 검증이 끝날 때까지 삭제하거나 덮어쓰지 마세요.
순서
  1. 원본 현황 기록
  2. ENEX 내보내기

  4. 전체 가져오기
  5. 결과 대조와 백업

1. 원본 현황을 먼저 기록합니다

노트북별 노트 수와 중요한 첨부 유형을 간단히 적습니다. 이미지, PDF, 음성, 표, 체크리스트처럼 형태가 다른 노트를 각각 표본으로 고르세요. 이후 결과가 맞는지 판단하는 기준이 됩니다.

동기화가 끝난 기기에서 내보내고, 저장 공간이 충분한지 확인합니다. 대용량 노트북은 한 파일로 몰지 말고 주제나 연도별로 나누면 실패 시 다시 시작하기 쉽습니다.

2. Evernote에서 ENEX를 내보냅니다

Evernote 데스크톱 앱의 내보내기 기능에서 ENEX 형식을 선택합니다. 파일명에는 노트북 이름과 날짜를 넣으세요. 예: 업무자료_2026-08-31.enex. 내보낸 파일은 복사본을 하나 더 만들어 별도 위치에 보관합니다.

ENEX 파일은 일반적으로 노트 내용과 일부 메타데이터, 첨부 리소스를 담지만 서비스별 기능이 완전히 동일하지는 않습니다. 작업 알림, 공유 권한, 일부 고유 서식은 옮겨지지 않을 수 있으므로 중요 항목은 별도 화면 캡처나 목록으로 남깁니다.

3. 작은 묶음으로 시험합니다

전체 자료보다 먼저 다양한 형식의 노트 10~20개가 든 작은 ENEX를 가져옵니다. 가져오기 중 브라우저를 닫지 말고, 완료 뒤 경고나 건너뛴 항목 수를 기록합니다.

  • 한글·영문 제목과 특수문자가 정상인가?
  • 긴 본문, 목록, 링크가 읽을 수 있는가?
  • 이미지와 파일 첨부가 열리는가?
  • 같은 파일을 다시 가져와도 뜻밖의 중복이 생기지 않는가?

4. 전체 자료는 나누어 가져옵니다

시험 결과가 맞으면 노트북별 ENEX를 하나씩 처리합니다. 각 묶음이 끝날 때 가져온 수와 원본 수를 대조한 뒤 다음 묶음으로 넘어갑니다. 오류가 난 묶음은 파일명과 시각을 기록해 다른 묶음과 섞이지 않게 합니다.

첨부가 매우 크거나 손상된 경우 노트 본문은 들어와도 일부 첨부가 빠질 수 있습니다. 이런 노트는 별도 목록으로 만들고 원본에서 직접 내려받아 보관합니다.

5. 검증 뒤 새 백업을 만듭니다

노트 수만 같다고 끝내지 말고 앞서 정한 표본을 실제로 열어 보세요. 결과가 만족스러우면 노트플러스P 내보내기로 새 백업을 만들고, 원본 ENEX와 다른 저장장치 또는 클라우드에도 복사합니다.

완료 조건: 원본 수 대조, 표본 열람, 첨부 확인, 새 백업 생성과 복원 시험이 모두 끝났을 때 이전이 완료된 것입니다.

문제가 생기면

앱을 반복 실행하기보다 원본을 보존한 채 작은 파일로 재현하세요. 사용 브라우저, ENEX 크기, 실패 시점, 경고 문구를 함께 기록하면 원인을 좁히기 쉽습니다.
